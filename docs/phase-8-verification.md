## Failures and fixes

1. An initial web-only typecheck ran before regenerated RPC declaration output was rebuilt. The subsequent root typecheck passed all 33 tasks.
2. The initial privacy integration run had 13 passes and one invalid fixture subreddit-name length failure. The fixture was corrected; the complete privacy suite and final integration rerun passed as recorded above.
3. A privacy follow-up was initially numbered before an already-applied operations migration. Supabase refused before SQL execution. The unapplied migration was renamed to the next sequential version. A second attempt found its stale generated copy; only that identical, never-applied copy was removed from the ignored service workdir. Corrected migration application passed. Applied migration files were never rewritten.
4. The first build failed when Turbopack could not bind its local child-process socket. An authorized retry reused the failed generated cache and also failed. Preserving that cache in ignored project-local diagnostics and rebuilding with a fresh cache passed. No security check or build feature was disabled.
5. First full unit run: 1,107 passed, four failed (80 files, 40.51 seconds). The existing runtime fixture omitted the privacy worker's local Storage key, and three hosted bootstrap tests found newly added local migrations missing from the explicit exclusion list. The synthetic fixture and exclusion list were updated. Final regression evidence is recorded in the table above.
6. First focused browser run: four passed and four failed, 1.3 minutes. Both operations journeys stopped at an implicit-label selector; the test now queries the control's actual accessible combobox name. Both CSP tests observed one script-policy violation. A diagnostic run identified Zod’s caught runtime code-generation probe; Zod now uses its interpreter in browser and extension entry points. The restrictive CSP and zero-violation assertion remain intact; rebuilt focused tests passed.

7. The initial fixture fix rerun still failed because the runtime SQL mock lacked `begin` and the hosted exclusion insertion had not matched its intended source marker. Explicit list updates and the transaction mock passed the final 14-test regression (520 ms), followed by the full 1,128-test pass.
8. The expanded privacy integration initially passed 18/20: one redaction assertion incorrectly classified permitted numeric AI token counts as secrets, and one fixture provider ID needed a valid format. Corrected focused tests passed 20/20 with secret-field exclusions still enforced.
9. Full integration regression: 236 passed, five failed across 15 files in 67.23 seconds (`.threadsignal/phase8-integration-full.log`). Four failures exposed the existing restricted Phase 2 worker’s inability to read the new organization-lock guard; the fix must retain narrow authority rather than grant broad organization access. The fifth was an older `SELECT *` receipt test touching newly protected export metadata. The worker now uses two narrowly granted job-eligibility/dispatch helpers instead of organization table access. The existing receipt test selects permitted fields and explicitly verifies protected artifact columns are denied. Focused worker 12/12 and Phase 1 17/17 pass; the complete rerun is recorded above.
