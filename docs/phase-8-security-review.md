# Phase 8 security and accessibility review

Review date: 2026-09-19. Target: the isolated repository and local Supabase application. This review did not use hosted credentials, external provider accounts, production customer records or existing browser sessions. It is not an independent penetration test, legal approval or production certification.

## Browser findings during integration

The first combined operations/accessibility run passed four of eight tests. Both public and authenticated three-width accessibility checks passed; both CSP cases observed one blocked eval, and two operations cases failed at a separate filter label. A diagnostic CSP-only run reproduced the blocked eval while framework nonces and React validation worked. Inspection of the installed Zod implementation identified its caught `new Function` capability probe, which deliberately falls back but still emits a violation. The client instrumentation entry point now sets `jitless: true` synchronously before hydration; both MV3 entry points do so before handling messages. The policy remains strict.

The rebuilt production rerun passed all eight operations/accessibility tests in 1.2 minutes. Both desktop and mobile CSP cases observed zero script violations while server-generated nonces and React validation worked; all four public/authenticated accessibility cases passed. Evidence: `.threadsignal/phase8-e2e-focused-rerun.log`. That run also logged two Next.js `The destination stream closed early` messages during the operations journeys, which completed successfully; these messages are not a failed assertion and are preserved rather than omitted. Full-suite and extension runtime results remain in the phase ledger.

Two safe HTML metadata probes ran after the temporary test server had already stopped and returned connection refused/unavailable. They inspected no HTML or credentials and did not establish readiness.

## Accessibility and performance scope

The new browser suite samples 320, 768 and 1280 px public layouts and authenticated notification settings; keyboard skip-link focus, headings, labels, reduced motion, actual computed text/button contrast and nonce-enabled hydration. It does not certify every WCAG success criterion, screen reader/browser combination or live Reddit editor. Contrast sampling covers solid-color foreground/background compositing, not every gradient/image state.

Dynamic nonce HTML intentionally gives up shared static HTML caching. Measure deployed marketing LCP under representative network/device conditions before claiming the specification's 2.5-second target. Provider metrics measure time until response headers, not streaming body completion. No Lighthouse score, production LCP, fleet latency percentile or uptime SLO is claimed from a local test. Tracking duration is a measured event, process operation timing is bounded local telemetry, and admin data represents current Supabase records rather than simulated real-time metrics.

Live Stripe/Resend/OAuth/AI, approved Reddit access, real crawler, HTTPS deployment, externally delivered alerts, backup restore, remote CI, Node 24 and Chrome Web Store/native live-editor compatibility remain separate verification steps. See [security boundaries](security.md), [responsible-use enforcement](responsible-use.md) and [release checklist](release-checklist.md).
