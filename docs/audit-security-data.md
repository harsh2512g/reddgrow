Scope: final specification audit of the completed Phase 0–8 implementation. This review covers database authority, job safety, deletion/retention, provider guardrails and repository hygiene. It does not activate a deployment or inspect private configuration. The final repository-wide result belongs in `SPEC_COMPLIANCE_MATRIX.md` and `IMPLEMENTATION_STATUS.md`.

## Verification record and failures

- Secret-pattern and clean-room policy suites: **50/50 passed**, 2 files, 263 ms (`.threadsignal/audit-harness-unit.log`). Focused ESLint exited 0.
- Billing-grace regression first failed on the old worker predicate; after the fix an overly broad fixture expectation counted legitimately filtered mock posts, then was corrected. Final **20/20 passed**, 3.37 s (`.threadsignal/audit-billing-grace-final.log`).
- Restricted deployment roles initially encountered a test import alias error, a catalog lookup that required private-schema access, and a driver JSON binding mismatch. Each was corrected. Then **11/11 passed**, 3.87 s (`.threadsignal/audit-runtime-role-final2.log`).
- Additional workflow/excerpt coverage exposed an invalid test fixture (`is_blocked=true` with `status=new`) in the subsequent full integration run. After correcting it to `status=blocked`, the updated role suite passed **11/11**, 2.68 s (`.threadsignal/audit-runtime-role-final3.log`). This includes explicit embedding-identity writes, invitation cleanup, authenticated workflow precedence, cross-tenant computed-field protection and excerpt truncation/purge.
- General AI accounting adds `private.record_ai_usage(uuid,uuid,uuid,text,jsonb)` to the exact worker/billing-bridge function boundary and `operation_id` to the safe export allowlist. The final expanded role suite passed **13/13**, 3.60 s (`.threadsignal/audit-runtime-role-final5.log`): metadata bounds, unknown cost, replay/collision, foreign organization/brand, browser-role denial and web member/task restrictions. Its first run had two harness errors: JSON strings needed explicit text-to-JSON casting, and the administrative test session can SET ROLE through its own membership. The latter assertion now checks the deployment web role's actual SET membership instead. The SQL helper trusts the web server's verified Auth-derived identity; it does not independently validate JWT signatures.
- The strengthened repository scan initially rejected four files containing literal synthetic credential patterns. After constructing those fixtures at runtime, it passed 682 repository text files. This is a supported-pattern scan, not a claim to detect every possible secret format.
- A later scan passed 735 text files. Full repository counts change as other audit agents add reviewed source and documentation.
- An early standalone web auth test could not start because `jsdom` was unavailable. Parent subsequently installed dependencies and owns the full unit-suite rerun.
- No hosted operation, external login, production provider call, Git commit or push was performed by this audit.

Current limitations: no live provider/deployment verification; no successful clean-room execution claimed by this document; final acceptance remains dependent on the root's current full-suite evidence and disposition of outstanding gaps.
