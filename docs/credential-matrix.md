# Credential boundaries

| Area               | Current local behavior                                                                                         | External integration boundary                                                                                         |
| ------------------ | -------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| Reddit             | Synthetic read-only mock                                                                                       | Injected-transport OAuth adapter implemented; explicit approved personal access and runtime activation still required |
| AI                 | Deterministic mock structured output/vectors                                                                   | New personal key and configured model identifiers                                                                     |
| Application email  | Console metadata only; message contents suppressed; private invitation link returned to the authorized inviter | New personal email provider configuration                                                                             |
| Billing            | Supabase-backed mock subscription lifecycle and atomic usage limits                                            | Checkout/Portal/signed webhook adapters implemented; test-mode configuration and runtime activation unverified        |
| Crawler            | Exact fixture URLs; no HTTP fetch                                                                              | URL validation and fixture ingestion implemented; live network crawler still unavailable                              |
| Supabase Auth      | Dedicated local containers; magic links delivered to the local inbox; verified user sessions                   | New personal Supabase project only, separately authorized                                                             |
| Google OAuth       | Disabled locally; guarded application entry point                                                              | New personal OAuth application and Supabase provider setup require explicit approval; not live-tested                 |
| PostgreSQL/storage | Dedicated local database, tenant RLS and private bucket; web access uses the user's Supabase session           | New personal infrastructure only, separately authorized                                                               |
| Redis              | Dedicated local loopback service for BullMQ and auth rate limits                                               | New personal infrastructure only, separately authorized                                                               |
| Monitoring         | Bounded safe operation/provider metrics and injected hooks; no external destinations                           | Separately authorized personal monitoring configuration                                                               |

The `.env.example` files list names with empty values. They are documentation, not files to populate with existing credentials. Local defaults come from code and the isolated runner. Keep `REDDIT_PROVIDER=mock`, `AI_PROVIDER=mock`, `EMAIL_PROVIDER=console`, `BILLING_PROVIDER=mock` and `CRAWLER_PROVIDER=fixture`. Matching real-provider secret fields are validated only when that provider is selected. Phase 8 retains these defaults and does not activate real adapters.

The existing root `.env.local` is never loaded. The launcher refuses app-local dotenv files that Next.js or other frameworks could otherwise auto-load. Local Supabase output is captured without displaying keys. Its guarded database URL, local public anon key and service ownership metadata are saved under ignored `.threadsignal/runtime.json` with owner-only file permissions. The public key must identify the `anon` role; a service-role credential is not accepted as public configuration. Container ownership is rechecked before applications receive local connection settings.

The web application uses the public Supabase configuration plus the authenticated user's session. PostgreSQL access through that session is subject to RLS. Guarded migrations, fixtures, integration tests and the local worker own operational database access. Public extension and attribution bridges connect only through fixed statements under separate restricted NOLOGIN roles; request input cannot choose SQL, a role or a database. No cloud secret or existing provider account is required. Session values and invitation links must not be printed, committed, included in screenshots or copied into documentation. Invitation storage contains only SHA-256 hashes of random 32-byte tokens, with expiry, revocation and verified-email checks.

Do not perform external login, deployment, account configuration or credential creation without separate explicit approval. Keep the historical local isolation exception visible in the verification record; no outside-repository inspection or cleanup is implied by this matrix.

## Extension and attribution credentials

The extension receives an expiring organization/user/origin-scoped opaque token, retained only in trusted extension storage; the database stores its hash. One-use connection codes and server conversion keys are never placed in source, screenshots or chat. Conversion keys are generated in Integrations, scoped to one brand, shown once, and copied only into the customer's own server secret configuration. Rotation immediately revokes the old key. No additional environment secret is required for the local Phase 6 implementation.

The browser snippet contains a public brand ID and endpoint, never a server key. Its click proof is a separate opaque capability carried briefly through the redirect query, scrubbed from the visible URL, and retained in a first-party cookie only after consent. Only its hash enters Supabase. Local diagnostics omit proof/key values and event payloads. The separately authorized hosted setup remains governed by the personal profile/worker documentation; these local commands do not inspect the existing root dotenv file or use hosted administrator credentials.
