# Step 13: review and remediation

Date: 2026-09-26. Baseline: `eaf24a7` on `main`, with the uncommitted Step 12 audit (125 tracked files changed, 69 added source files). The initial pass was read-only. No commit, push, external login, hosted migration or real-provider activation is part of this step.

## Findings and fixes

1. **P1 — Website preview failed before invoking the real crawler.** In `apps/web/src/lib/knowledge/api.ts`, `sourcePages` parsed the table-valued `get_organization_plan` response as an object. Supabase returns an array, as the existing organization loader correctly expects. An owner selecting website pages with `CRAWLER_PROVIDER=simple` received a server error. The preview now reads the authenticated `get_billing_subscription` JSON contract, verifies current eligibility and uses its plan to bound candidates. Tests cover trial/Solo/Growth, manager permissions, archived brands, expired plans and unavailable authority with an injected crawler; no external website was fetched.

2. **P1 — Web AI operations could spend provider capacity after subscription expiry.** `apps/web/src/lib/env/ai-usage.ts` invoked the operation after rate limiting, without checking the current subscription. The extraction and suggestion handlers authorize membership, but membership alone does not establish paid eligibility. `apps/web/src/lib/provider-plan.ts` now asks Supabase for the current authorized subscription before embeddings, keyword suggestions, community suggestions or product extraction. The database determines eligibility using its own clock and payment-grace rules; a missing, malformed or wrong-organization result fails closed. The frozen personal Phase 2 mock-only profile is preserved. Existing knowledge records remain readable.

3. **P1 — Failed and stale draft attempts were absent from cost accounting.** `apps/worker/src/jobs/drafts.ts` supplied usage only to successful publication RPCs. A billed malformed response followed by a retry could disappear from the job total. Additive migration `20260926000000_draft_attempt_accounting.sql` introduces private, bounded receipts keyed by job/attempt and lease identity. The worker records each claimed attempt in `finally`, independently of publication, then the helper aggregates all available attempts into the existing single public usage row. Identical replay is idempotent; conflicting replay fails. Missing receipts or unknown usage/prices leave totals unknown. No prompt, source, draft, error payload or credential is stored in these receipts. Organization deletion cascades through the job to the receipts. The restricted worker receives only the new helper; browser and bridge roles receive no private-table authority.

4. **P2 — Release instructions were stale.** The release checklist still described the deployment runtime and crawler implementation as absent after Step 12 implemented them. It now distinguishes implementation evidence from the still-required external provisioning and live acceptance.

## Failures and resolutions

- The first full integration attempt exited 1: 264 passed and four service tests skipped after the service test file could not bind port 3001. A prior development worker owned the port. Stopping the old terminal session returned exit 130 but left child processes alive.
- The second integration attempt exited 1: 262 passed, two failed and four skipped. The same port collision remained; the background worker also raced the controlled plan-grace job tests. The Next and worker parents/children were identified by their repository working directories and local listeners, stopped, and both ports were verified free. The final isolated run passed all 268 tests. No plan or authorization assertion was relaxed.
- Initial typecheck exited 2 and the first build exited 1 because the new safe error map duplicated an existing `PLAN_UNAVAILABLE` key. The duplicate was removed; both final commands passed.
- Some read-only discovery commands referenced absent files and returned nonzero; paths were corrected without creating replacements. One malformed patch and one guarded documentation text replacement were rejected before any write. These were tooling/discovery mistakes, not hidden passing checks.
- The lint/format/extension-build output from one parallel tool response was truncated. The explicit final invocations/results above are used instead of inferring exit codes from the missing response.
