# Security review

Phase 8 reviews the current local Supabase application. This is an engineering review, not an independent penetration test or a claim that hosted production is ready. Exact executed results belong in [Phase 8 verification](phase-8-verification.md). No hosted credentials, provider accounts or existing browser sessions were inspected.

## Hardening decisions

Document responses use an unpredictable 192-bit nonce generated in the proxy. Incoming nonce/CSP/request ID headers are overwritten. Next receives the same policy before rendering framework scripts; the root layout waits for a request, so nonce-bearing HTML is dynamic and not shared in a CDN cache. Production builds do not permit script `unsafe-inline` or `unsafe-eval`. Development permits eval for the Next debugger and only the two configured loopback HMR websocket origins. Styles allow inline attributes required by React/Radix/chart dimensions; this does not allow inline scripts. Zod is configured synchronously in interpreter mode before browser hydration; its optional eval capability probe is disabled rather than weakening CSP. MV3 entry points use the same interpreter setting. No third-party analytics script is enabled. Public API CORS remains endpoint-specific.

Knowledge, opportunity and draft mutation APIs admit at most 120 requests per organization/family/minute and 1,200 globally/family/minute. The scope is hashed, never a raw IP or email. Role checks run first; a rate-limit backend failure returns 503 before business writes. These HTTP controls supplement database plan reservations; they are not a substitute for the public Supabase gateway's own abuse controls. Production requires an explicitly authorized TLS Redis profile and ingress request limits; local-only guards must not be removed to make deployment appear to work.

Telemetry permits IDs and fixed operation labels, not arbitrary provider bodies. Shared logger sanitization bounds nesting/collection/string size and redacts credential/content keys, URLs, email values and Error details, including interpolation arguments. Message templates must still be fixed strings: arbitrary opaque values cannot be recognized reliably as secrets. Optional error/tracing/metrics sinks must not alter the operation's outcome.

Private platform audit and retry records have bounded 180-day retention. Manual job retries expire after 90 days and remain limited to one per original job; cleanup cannot reset an eligible job's allowance. Tenant activity retention is also 180 days, while export expiry and other data-specific rules are documented in [privacy and data flow](privacy-data-flow.md). Retention is enforced through worker maintenance, so a stopped worker is not evidence of completed physical deletion.

## Dependency posture and unresolved release boundaries

On 2026-09-19 the isolated public npm production audit returned zero advisories across 183 production dependencies. The full dependency audit also returned zero advisories across 688 dependencies, including build/test tooling. An audit is a time-specific advisory lookup, not proof of absence of vulnerabilities. Re-run the audit and all quality gates at each release; do not use an automatic force-upgrade that changes the tested lockfile.

Hosted Phases 3–8, external Stripe/Resend/AI/Reddit, HTTPS deployment, Node 24 and remote CI are not established by local tests. The specification audit implements the guarded network crawler, explicit deployment profiles and checked restricted worker/API authority. Their injected-transport and local privilege tests do not establish hosted operation; separate authorized provisioning and live verification remain necessary.
